# T21 · 实体 ↔ 电子长河令兑换

- 状态：🧪 代码完成 · 云函数已部署
- 依赖：T10（员工模式）、长河令账户体系（ling_accounts / ling_ledger）

## 目标

客户实体长河令没用完 → 员工回收，转成电子令存入账户（下次可用）；反向电子令兑实体，
电子令对应核减。双向、留痕、可对账。

## 关键决策（已锁定）

1. **客户定位**：新增「我的令码」——任何登录用户（不限会员）出示动态令码，员工扫码定位其电子令账户。
2. **权限**：front / admin 均可操作，不限额（单笔上限 100 万令防误输）。
3. **防转让**：令码为动态 token（`UL.<openid>.<ts>.<sign>`，90 秒失效，HMAC 签名），复用 `MEMBER_QR_SECRET`。

## 云函数

| 函数 | 职责 |
|---|---|
| `getUserQr` | 生成用户「我的令码」动态 token（含 openid） |
| `resolveUserForLing` | 员工扫码（UL 令码 / MC 会员码 / 静态会员码）→ 解析 openid + 返回余额 |
| `exchangeLing` | 兑换：p2d 实体转电子（+）/ d2p 电子兑实体（−，余额不足拒绝）；事务 + `ling_ledger` 留痕 |

## 页面

| 路由 | 端 | 职责 |
|---|---|---|
| `pages/ling/mycode/mycode` | 客户 | 展示动态令码 + 电子令余额（从「我的」进入） |
| `pages/staff/ling-exchange/ling-exchange` | 员工 | 扫码 → 显示余额 → 选方向 + 输数量 → 兑换 |

## 安全 / 正确性

- 客户身份、金额均由云端从签名码解析，不信前端。
- `d2p` 事务内校验余额充足，防透支。
- `ling_ledger` 记 `type`（physical_to_digital / digital_to_physical）+ `staffOpenid`。

## 验收

- [ ] 客户「我的令码」动态刷新，员工可扫
- [ ] 实体→电子：电子令正确增加并留痕
- [ ] 电子→实体：余额不足被拒；充足则核减并留痕
- [ ] 令码过期不可用；非会员客户也能兑换

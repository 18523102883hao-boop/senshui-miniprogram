# T12 · 溪降检票核销（扫码 / 一次性 token / 人数台账）★下一阶段核心

- 状态：📄 下一阶段
- 依赖：T10, T11

## 目标
检票员扫预约码核销，人数计入当场台账，重复扫码拦截，台账可导出。

## 实现
- 员工端（role: creek/admin）扫 booking 的 `code`。
- 云函数 `verifyBooking`：
  - 事务/条件更新：`bookings.where({ code, status:'reserved' }).update({ status:'verified', verifiedAt, verifierOpenid })`；`updated===0` → 已核销/无效 → **拦截**（一次性 token 失效）。
  - 写 `verifications`（type:'creek_ticket'）全量留痕。
  - 人数计入当场台账（可实时聚合 verified 数 / 冗余 session.verifiedCount）。
- 对齐安全员人数清点制度：台账按场次导出（管理员 `exportVerifications`）。

## 验收
- [ ] 重复扫码被拦截（一次性 token）
- [ ] 当场核销人数准确
- [ ] 台账可按场次导出
- [ ] 无网降级：预约码离线可出示，恢复网络后核销

## 目标
按日配置溪降场次与容量，提供**并发安全、线上线下同池**的占位/释放能力，杜绝超卖。

## 数据模型 `sessions`
```
{
  _id,
  date: Date,          // 当天 00:00，按日筛选
  startTime: '13:00',  // 场次开始
  capacity: 20,        // 容量上限（对齐溪降限流标准，待拍板）
  remaining: 20,       // 剩余（= capacity - 已占），扣减基准
  booked: 0,           // 已占（线上+插单，冗余便于台账）
  status: 'open',      // open | closed（天气/水位停运一键关闭）
  note: '',            // 停运原因等
  updatedAt: Date
}
```
> `remaining` 与 `booked` 双字段：`remaining` 用于原子条件扣减，`booked` 用于台账展示。

## 关键算法：原子扣减（防超卖）
**推荐用「条件更新」而非事务**——单条文档原子操作，高并发安全：
```js
const _ = db.command
const res = await db.collection('sessions')
  .where({ _id: sessionId, status: 'open', remaining: _.gt(0) })
  .update({ data: { remaining: _.inc(-1), booked: _.inc(1), updatedAt: new Date() } })
if (res.stats.updated === 0) {
  // 满员 / 已关闭 / 被并发抢占 → 占位失败
  return { code: 409, msg: '该场次已满或已关闭' }
}
// 占位成功后再写 bookings（失败需回补 remaining+1）
```
> 不能用 `remaining < capacity` 这类**字段间比较**（云数据库 where 不支持）；改用常量比较 `remaining > 0`。

## 云函数
| 函数 | 职责 |
|---|---|
| `holdSeat` | 原子扣减占位（供 T08 预约 / T11 插单共用，**同一池**） |
| `releaseSeat` | 释放：`remaining:_.inc(1), booked:_.inc(-1)`（改签/取消/未到释放） |
| `closeSession` | 一键关闭场次 `status:'closed'` + 触发停运通知（T09） |
| `listSessions` | 按日期查场次余位（C 端 + 员工余位面板 T11 共用） |

## 边界
- 占位成功但写 bookings 失败 → **必须回补** `releaseSeat`（补偿事务思路）。
- 关闭场次不影响已占记录，但阻止新占。
- 容量修改（调大/调小）需同步 `remaining`（谨慎：调小不能让 remaining 为负）。

## 验收

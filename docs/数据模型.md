# 数据模型（云数据库集合）

金额单位统一为**分**。时间统一 `Date` 类型。用户身份统一以 `_openid` 关联。

> ★ = V1 本轮已使用；☆ = 下一阶段 / V2 预留

## members ★（会员卡）
| 字段 | 类型 | 说明 |

| _openid | string | 持卡人 |

**必须索引**：`_openid + outTradeNo` 唯一复合索引（同一用户同一订单只保留一条可修订申请）。
**查询索引**：`status + updatedAt` 普通索引。集合权限设为“所有用户不可读写”，只允许 `invoiceService` 及退款云函数访问。
**文件规则**：仅接受 `invoice-files/{requestId}/` 目录下的单个 PDF，最大 10MB；客户端先检查扩展名、大小和文件头，`invoiceService` 下载后再次检查真实大小及 `%PDF-` 文件头。普通用户仅可获取本人且状态为 `issued` 的临时访问地址，管理员可在审核中预览。

## 管理员运营与对账（只读视图）

第一阶段业务账不新增事实集合，由 `adminOperationsLedger` 只读汇总以下数据：

- 资金实收：`orders.paidAt + amount/totalFee`
- 门票退款：`tickets.refundedAt + unitPrice`
- 会员退款：`members.refundedAt + orderId` 关联原订单金额
- 待退款：`refund_requests.createdAt + status + refundFee`
- 门票核销：`tickets.usedAt + verifiedBy + unitPrice`
- 历史预约及会员核销：`verifications.createdAt`
- 长河令兑换：`ling_ledger.createdAt`

报表中的核销票面金额不计入收入，长河令不折算现金。建议为报表时间字段建立普通索引：
`orders.paidAt`、`tickets.usedAt`、`tickets.refundedAt`、`members.refundedAt`、
`refund_requests.createdAt`、`verifications.createdAt`、`ling_ledger.createdAt`。

门票核销必须同时保留两个口径：`ticketCount`（核销票数，单张票固定为 1）和
`admissionCount`（实际人数）。新票从商品、订单、票券逐级固化快照；历史已知 SKU
允许按当前明确规则回填，无法识别的历史票必须标记 `admissionCountUnknown: true`，
不得擅自按 1 人计入实际人数。

## 领域状态常量（单一真源）

以下取值的**唯一定义处**是 `miniprogram/utils/domain.js`，云函数各自复制时必须与此表一致；
契约由 `tests/feature-expansion/contracts.test.js` 锁定，改动状态值会导致该测试失败。

| 常量 | 取值 | 来源 |
|---|---|---|
| `ORDER_TYPES` | `member_card`、`ticket_upgrade`（已上线，不可改）、`ticket_order`（新增）、`rental_order` / `retail_order`（预留） | PRD §14.4 |
| `TICKET_STATUS` | `unused`、`reserved`、`used`、`refund_pending`、`refunded`、`expired`、`void` | PRD §8.6 |
| `VISIT_RESERVATION_STATUS` | `pending`、`confirmed`、`completed`、`cancelled`、`rejected` | PRD §17.6 |
| `FEEDBACK_STATUS` | `submitted`、`processing`、`resolved`、`closed` | PRD §15.2 |

**金额约定**：全站金额一律以「整数分」在前后端流转，元只出现在展示层，由 `domain.js` 的 `fenToYuan()` 转换；
该函数对非整数分（如 `9.9`、`'990'`）直接抛错，防止浮点元被误写进订单。

**本轮新增集合**（集合名已登记在 `miniprogram/utils/const.js` 的 `COLLECTIONS`，字段随各任务落地时补充到本文档）：
`home_configs`、`articles`、`ticket_products`、`tickets`、`visit_reservations`、`feedback`、`itineraries`、`ling_daily_quotas`。
门票订单复用 `orders` 集合，以 `type: 'ticket_order'` 区分（PRD §17.4）。

# 员工工作台、补差价数量与线索下线设计

日期：2026-07-28  
状态：已确认

## 1. 目标与范围

本轮同时完成三项相互关联的收口工作：

1. 将员工模式入口重构为适合现场高频操作的角色化工作台，并统一为「长河令江湖」深色视觉语言。
2. 让全部 7 个补差价升级项目支持一次购买 1–10 份，默认 1 份，金额始终由云端官方单价计算。
3. 将「线索跟进」完整下线，删除用户端、员工端、云函数、路由、测试和现行文档中的功能实现，并把仍需咨询的入口改为直接联系管家。

本轮不改变会员核销、门票核销、长河令兑换、补差价支付、财务对账、开票管理等业务模型。

## 2. 员工工作台信息架构

### 2.1 页面状态

员工入口使用四个互斥状态，禁止以「未绑定」兜底所有异常：

- `loading`：正在查询身份，显示深色骨架状态。
- `error`：网络或云函数异常，显示错误说明和重新加载操作。
- `unbound`：查询成功但没有有效员工身份，显示员工登记表单。
- `bound`：查询成功且身份有效，按角色展示工作台。

`checkStaff` 失败不得展示登记表单，避免员工重复绑定或误以为权限丢失。页面在 `onShow` 重新查询身份；较早请求返回时不得覆盖较新的页面状态。

### 2.2 角色与任务优先级

任务顺序由稳定的角色配置决定，不根据个人点击历史移动，避免不同手机上的操作位置漂移。

| 角色 | 主任务 | 高频任务 | 管理任务 |
| --- | --- | --- | --- |
| 前台 `front` | 补差价收款 | 门票核销、长河令兑换、会员核销 | 无 |
| 溪降检票 `creek` | 门票核销 | 会员核销 | 无 |
| 酒吧/小卖部 `bar` | 会员核销 | 无 | 无 |
| 管理员 `admin` | 门票核销 | 补差价收款、会员核销、长河令兑换 | 运营与对账、开票管理、园区地图管理 |

「线索跟进」不再出现在任何角色配置中。

### 2.3 页面层级

1. 紧凑身份区：员工姓名、角色、当班状态，不占用过多首屏空间。
2. 主任务：使用整行大卡，突出现场最常用操作。
3. 高频任务：两列网格，每个入口包含图标、标题和一句操作提示。
4. 管理员今日概览：净收入、实际入园人数、核销票数、待处理开票或异常；概览失败不影响现场操作入口。
5. 管理工具：对账、开票、地图等低频入口位于页面下部。

管理员概览优先复用现有运营汇总能力；开票待处理数使用轻量统计，不通过拉取完整申请列表计算。

### 2.4 视觉和交互

- 页面背景使用 `--sr-dark-bg`，卡片使用 `--sr-dark-card` / `--sr-dark-card-2`。
- 主文字使用米白色，次要文字使用深色主题弱化色，数据和状态徽标使用 `--sr-gold`。
- 朱砂/珊瑚色只用于主操作强调、危险动作或错误状态。
- 复用现有森林/米白图标，不使用 Emoji。
- 现场操作入口最小高度 88rpx，卡片之间至少 16rpx。
- 按压反馈仅使用 180–240ms 的透明度/缩放动画和轻触觉反馈。
- 不使用横向滚动或隐藏手势，避免戴手套、湿手或单手操作时误触。
- 管理员统计加载失败时保留入口，并提供独立重试；角色未知或被撤销时安全阻断。

## 3. 补差价升级数量

### 3.1 用户流程

1. 用户选择当前持有票种。
2. 点击任意升级项目，打开底部确认面板。
3. 面板统一显示「购买数量」步进器，默认 1，可选 1–10。
4. 实时展示「官方单价 × 数量 = 应付总额」。
5. 用户可填写接待员工手机号后四位并发起支付。
6. 支付成功页显示升级项目、购买数量和实付金额。

所有 7 个升级项目使用相同数量交互。双人溪降票不再默认 2 份；用户仍可购买 1 份或一次购买多份。

### 3.2 计价与兼容

- 客户端只提交 `itemId`、`quantity` 和可选 `staffRef`，不提交可信金额。
- 云函数按当前启用升级项的官方单价重新计算 `unitPrice × quantity`。
- 云端数量范围为整数 1–10；`0`、`11`、小数、非数字一律拒绝。
- 旧客户端缺少 `quantity` 时按 1 份兼容。
- 订单继续保存 `quantity`、`unitPrice`、`totalFee`，并在标签中体现数量。
- 支付取消或业务校验失败时保留用户已选择的项目、数量和员工尾号，便于重试。
- 页面明确提示：升级订单必须与原票同时核验，不能独立作为入园凭证。

## 4. 线索跟进完整下线

### 4.1 删除范围

- 删除用户端线索表单和「我的咨询」页面。
- 删除员工端线索列表、认领、状态跟进页面和工作台入口。
- 从 `app.json` 删除相关页面注册。
- 从「我的」页面删除「我的咨询」菜单项。
- 删除 `createServiceLead`、`getMyServiceLeads`、`listAssignedLeads`、`updateServiceLead` 四个云函数目录。
- 从常量、领域状态、数据库初始化、部署辅助脚本中删除活动引用。
- 删除专属自动化测试，并把跨功能测试改为断言不存在废弃路由。
- 从现行数据模型、业务参数、数据库初始化和 UI 审计文档中删除活动功能说明。

历史实施计划属于变更记录，不改写其当时内容；新设计和实施计划明确该能力已废弃。

### 4.2 替代流程

- 咨询型商品和特色服务保留展示能力。
- 需要人工咨询时直接进入现有管家联系方式或拨打电话，不再创建线索记录。
- 删除后增加静态契约测试，防止废弃页面、云函数和路由被误恢复。

### 4.3 数据保留与云端删除

- 本轮不批量删除线上 `service_leads` 历史集合和记录，避免不可恢复的数据损失。
- `initDb` 不再为新环境创建该集合，代码也不再读写它。
- 部署前先只读列出云端函数，确认名称后仅删除上述四个已废弃函数。
- 若 CLI 当前不具备远程删除能力，代码侧仍完成下线，并输出精确的人工删除清单。

## 5. 权限、失败和安全边界

- 所有员工业务页面继续在云函数端检查员工状态和角色；工作台隐藏入口不是权限控制的替代品。
- 管理员汇总数据与基础身份查询解耦，汇总异常不得把管理员误判成未绑定。
- 请求失败显示业务可读文案，不直接向用户暴露 CloudBase 错误码或调用栈。
- 升级数量和金额均由服务端校验；客户端边界控制仅用于交互反馈。
- 删除线索功能后不删除历史数据库数据，也不扩大任何员工的数据访问权限。

## 6. 验证策略

### 6.1 员工工作台

- 四态渲染正确，网络失败不出现登记表。
- 四种角色的主任务、高频任务和管理任务顺序精确。
- 页面不存在「线索跟进」和废弃路由。
- 深色 Design Token、最小触控高度、现有图标和按压反馈符合规范。
- 管理员概览失败时任务入口仍可操作。

### 6.2 升级购买

- 7 个升级项默认数量均为 1。
- 每个升级项均可选择 1 和 10，不能越过边界。
- 云端拒绝非法数量，并忽略伪造客户端金额。
- 支付请求携带当前数量，取消支付保留选择。
- 成功态展示数量和云端金额。

### 6.3 线索下线

- 废弃页面和四个云函数目录不存在。
- `app.json`、员工入口、「我的」页面、部署辅助脚本和活动文档中不存在废弃引用。
- 咨询型商品直接进入管家联系方式。
- 全量 Node 测试和关键 JavaScript 语法检查通过。

## 7. 实施顺序与逐页自测

1. 员工模式入口：先写失败测试，再重构页面；完成后输出并执行页面自测清单。
2. 线索功能下线：先写退休契约测试，再删除页面、云函数和活动引用；执行导航回归。
3. 补差价升级页：先改测试，再统一 1–10 数量交互；完成后输出并执行页面自测清单。
4. 补差价云端：更新订单纯逻辑和配置，验证服务端计价及旧客户端兼容。
5. 运行聚焦测试、语法检查和全量测试；最后核对并执行精确的云函数部署/删除。

## 8. 风险

- 员工入口当前把网络错误当作未绑定，重构时必须显式区分状态。
- 线上可能仍有旧客户端调用已下线云函数；删除后这些调用会失败，但当前小程序版本不再提供入口。
- `service_leads` 历史集合保留但不再有前端访问路径，需要后续单独的数据归档策略。
- 线上升级项配置可能缺少数量上限字段，云函数应提供安全默认值 10，并保持官方单价权威。
- 工作区存在未提交的阶段性修改，本轮必须逐文件编辑，禁止覆盖或回滚无关改动。

# 游客端补差升级页 UI/UX 设计

## 目标

在不改变七个升级项目、云端锁价、员工归属和微信支付链路的前提下，将游客端 `pages/upgrade-info/upgrade-info` 改造成先判断当前票种、再选择升级项目、最后确认支付的低认知负担流程。

## 范围

本次只修改游客端补差升级页及其页面级自动化测试。

不修改：

- `createSelfUpgrade` 云函数及其参数。
- 员工开单页 `pages/staff/charge/charge`。
- 顾客扫码支付页 `pages/pay/upgrade/upgrade`。
- 全局样式、tabBar、其他页面或业务路由。
- 七个升级项目的 `itemId`、价格文案和权益内容。

## 交互设计

1. 首屏不再以 `¥178` 作为主要决策信息，改为说明“已买单项票，也能补差升级”。
2. 首先询问“你当前持有什么票”，默认选择营地票，并提供营地票、溪降票两个整块选择项。
3. 页面只展示当前方向对应的三至四个升级选项。
4. 每个选项整行可点，右侧只展示本次补差金额和箭头，不重复显示“立即补差”按钮。
5. 点击选项后打开底部确认面板，明确当前票种、升级所得和本次应付金额。
6. “接待员工”保持选填，但默认折叠在“有现场员工接待？”下，并说明该信息只用于服务归属，不影响升级权益。
7. 微信支付是页面唯一强行动按钮。
8. 支付成功后在当前页面展示结构化结果态，包含升级项目、已付金额和现场核验说明；不伪造持久订单号。

## 视觉方向

- 采用自然高级的暖白底和森林绿主层级。
- 主要内容尽量平面化，使用细边框与留白，不把每个模块都包装成独立白卡。
- 珊瑚色只用于本次应付金额和微信支付动作。
- 金色只用于套票权益提示，不承载小字号正文。
- 玻璃效果仅用于底部确认面板，并提供不支持模糊时的实体背景。
- 动效限定为方向切换、选项按压和底部面板进入，不新增循环装饰动画。

## 数据与状态

页面保留原 `groups` 数据作为升级项目唯一前端映射，并新增：

- `activeGroupIndex`：当前升级方向。
- `visibleItems`：当前方向可见项目。
- `staffExpanded`：接待员工输入区是否展开。
- `success`：本次支付成功后的临时页面状态。

提交支付仍调用：

```js
request.callWithLoading('createSelfUpgrade', {
  itemId: buy.itemId,
  staffRef: staffRef
}, '下单中')
```

支付成功状态使用云函数返回的 `itemLabel` 和 `amount`，不信任页面展示价格作为交易金额。

## 异常处理

- 用户取消微信支付：保持确认面板和已填员工信息，便于重试。
- 云端失败：保持当前选择，通过现有 Toast 显示错误。
- 支付期间：禁止关闭面板、切换项目和重复提交。
- 未匹配员工：由现有云端逻辑处理，不在页面阻断支付。

## 验证标准

- 七个 `itemId` 完整且只出现一次。
- 两个方向切换后分别只展示四项和三项。
- 项目选择、面板关闭、员工信息展开、支付取消和成功状态均可验证。
- WXML 不再出现通用大价 `¥178` 和重复“立即补差”。
- 最小操作目标达到 88rpx。
- 页面不引用新图片，不增加主包资源。
- 只允许 `upgrade-info` 页面、页面测试及本设计/实施文档发生变化。

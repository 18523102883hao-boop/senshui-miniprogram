# 经营数据中心口径与导出重构设计

## 决策

采用“事实域优先”的信息架构，不再用一个混合账单同时服务财务和运营：

- 收入识别：订单收入与实际净收入。
- 资金账本：支付、实际退款和资金流水净额事实。
- 入园核销：门票履约事实，核销金额就是实际净收入。
- 业务数据：长河令与会员卡兑换事实。
- 数据导出：管理员统一选择范围、数据类型和字段。

导出载体采用一个 Excel 文件，每个数据类型一个工作表。Excel 由云函数生成并上传临时云文件，小程序下载后通过 `wx.openDocument` 打开，用户可使用微信文件菜单另存或转发。

## 指标词典

| 指标 | 事实来源 | 时间轴 | 禁止别名 |
| --- | --- | --- | --- |
| 订单收入 | 已支付未核销的有效门票 | 当前有效票状态，按订单支付范围查询 | 实际净收入 |
| 实际净收入 | 已使用票券单价合计 | `usedAt` | 资金流水净额 |
| 支付金额 | 支付成功订单 | `paidAt` | 实际净收入 |
| 退款金额 | 实际完成退款 | `refundedAt` | 待退款金额 |
| 资金流水净额 | 支付金额 − 退款金额 | 各自发生时间 | 实际净收入 |
| 支付订单 | 支付成功去重订单 | `paidAt` | 核销订单 |
| 核销票数 | 已使用票券 | `usedAt` | 实际人数 |
| 实际人数 | 票券 `admissionCount` | `usedAt` | 核销票数 |
| 关联订单 | 含核销票券的去重订单 | `usedAt` | 支付订单 |

“已核销票面金额”只作为“实际净收入”的口径解释，不再作为独立展示指标。

## 页面层级

经营数据中心首页默认今天，先展示订单收入与实际净收入，再提供资金账本、入园核销、业务数据和导出入口。资金账本、入园核销分别持有自己的周期筛选、统计和明细；业务数据保留三类汇总与下钻。

## Excel 工作表

`导出说明`始终存在。其余工作表由管理员勾选：

1. `收入与资金汇总`
2. `支付明细`
3. `退款明细`
4. `核销汇总`
5. `核销明细`
6. `票种统计`
7. `业务汇总`
8. `业务明细`

每张表使用固定列定义，前端字段选择只允许在白名单内取子集。服务端忽略未知字段，禁止客户端注入任意属性。任何来源达到截断上限时返回业务错误，不生成可能被误当完整账目的文件。

## 失败与隐私

- 导出：失败保留选择条件；文件过期可重新生成。
- 反馈图片：取消静默，其他失败显式反馈；兼容 `chooseImage`。
- 发票 PDF：取消静默，声明错误给出后台配置路径。
- 所有导出继续隐藏 openid，手机号只保留后四位。

## 验证

- 纯逻辑测试验证指标映射、工作表选择、列白名单和脱敏。
- 页面测试验证导航与文案不会再次混用。
- 开发者工具验证 Excel 打开、反馈图片选择和发票 PDF 选择。
- 320px 等效视口检查人数步进器不溢出。

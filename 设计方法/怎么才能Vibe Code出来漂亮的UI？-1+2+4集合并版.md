## 二、第一集 · 审美积累

> **视频**：[BV1V5Eu68E5m](https://www.bilibili.com/video/BV1V5Eu68E5m) · b23.tv/3Qtu9FX
> **发布**：2026-06-08 · 5 分 00 秒 · 12.1 万播放

### 一句话核心

> Vibe Code 出来的 UI 丑，**根本原因不是工具不行，是你脑子里没有"好看"的样本。**
> 第一步不是学 prompt，是**做审美积累**。

### 核心论点

> **Taste is all you need.** ——到了 AI 时代，你的品位就是你的一切。

很多时候大家忘了审美积累这个过程。**你需要用过好的 App、好的产品、好的交互，你才有个概念**：它这里有一个振动，那里是这样划过去的，那边是这样子处理的。你才知道说你的 App 可以应用在这个地方。

> **简单来说就是：抄。我的 App 也是抄出来的。** 我结合了很多很棒的设计放到一起，看上去就蛮有质感。"你是怎么 Vibe 出来的？"

### 推荐 6 个值得抄的 App

| # | App 名 | 借鉴点 | 备注 |
|---|---|---|---|
| 1 | **记绩**（Achievement / Hack） | 震动反馈 / 主视图 / 俯视图 / 设置页 / 付费墙 | UP 主本人作品，**直接抄就完事** |
| 2 | **印书**（Inkpad） | 整一个手绘感觉、阅读类印刷质感 | 借鉴自海外 App **Margins** |
| 3 | **感叹号天气**（！） | 交互动效 | 功能平平但卖得上价，**靠动效吃饭** |
| 4 | **未知书** | 细节交互 / 震动反馈 / 图片出现方式 | 作者：赵纯祥 |
| 5 | **Apollo** | 电影收集打卡 / 数据传递方式 | 看的是"**数据之间怎么传递**"不是布局 |
| 6 | **Pinterest** | 不知道页面怎么设计就去这里**抄** | 实操举例：成就页设计就是从 Pinterest 找的参考 |

### 三个结论

1. **完成审美积累是第一步** —— 把好看的 App 放到一个专门的地方
2. **这是一整套流程，不是一键 Skill** —— 没有"啪"一下就能帮你搞定的事情
3. **审美积累 + 创意缺一不可** —— 就算用 AI 拍电影/做短片也一样

### 关键引用

> "我结合了很多很棒的设计放到一起——所以你抄我就相当于我已经替你抄完了这些大师的作品，所以你抄就完事了。"

> "感叹号天气所有功能都平平无奇，但它依然能卖得上价——原因就是它的交互动效做得非常好。"

## 三、第二集 · Style.md（视觉规范）

> **视频**：[BV1V5Eu68E5m 之后的二集，b23.tv/oVcb1hr](https://b23.tv/oVcb1hr)
> **发布**：2026-06-08 之后 · 4 分 16 秒

### 一句话核心

> **好看的 UI 一定不是"一个按钮好看或一个布局好看"就完事。**
> **好看的 UI 一定从整体上就是美的——靠 Style.md 来锁住整体。**

### 流程四步（UP 主真实做"印书"App 的对话记录）

#### 第 1 步：扔参考图

把第一集里找到的好看参考图（Margins 那种）**两张扔给 AI**。

> "这是第一张参考图，这是第二张参考图。"

#### 第 2 步：聊产品定位 + PRD

跟 AI 说清楚：
- 我打算做一个 AI 生图 App
- 功能很简单
- 首先要确定**整个 PRD 流程**（产品需求文档）
- **定位：极简复古杂志风格**
- 要非常简单
- 帮我想一个名字（往 "film / 相纸" 这类概念靠）

AI 会回一长串产品定位、功能、命名建议。

#### 第 3 步：让 AI 生成主视觉变体

> "OK 我把名字确定下来了，主视觉啊，做笔记啊——就是按照我提供的风格生成若干版的变体供我参考。"

AI 会给一堆 **mockup**（样机图）。UP 主说"我有了 5 个 mockup"——**1、2、3、4 我就做选择题**，挑一版最喜欢的。

#### 第 4 步：让 AI 输出 Style.md

> "接下来的魔法就是——我让他给我一版 **style.md**，包括风格、字体、间距、颜色的要求。"

AI 给一份完整的 Markdown 格式风格规范文档（**这就是"Style.md"名字的由来**——style 的 MD）。

### 关键心法

> "**style.md 你可以简单理解为有一个设计师，它规范了所有的框架。**"

拿到 Style.md 后，你**复制 / 下载**，以后再做功能时——

> "比如你希望有一个按钮 / 一个视图 / 一个页面，你在 Codex 里也好，在 Cursor 里也好，你**@ 这个 style.md 跟他说：你就按照这样的风格去给我做，就不会有任何的问题**。"

> "因为他这里有**所有的东西**——文案语气、视觉规范、希望用什么字体、颜色是什么样子的——他就**全部都帮你弄好了，所以就不会跑偏**。"

### 避坑（为什么你扔了参考图还是做不好？）

> "如果有人说我把那个参考扔给他了，结果他做出来还是一言难尽——**是因为你总是先关注细节，而没有先有一个 Style.md 去约束它**。"

### 关键引用

> "**style.md = 一个设计师，规范了所有框架。**"

> "你**@ 这个 style.md** 跟他说按这个风格做，就**不会跑偏**。"

> "做不好是因为**你先关注细节，而没有 Style.md 先约束**。"

## 四、第四集 · UI vs UX：先想交互再想视觉

> **视频**：[BV1qfTF6EEno](https://www.bilibili.com/video/BV1qfTF6EEno) · b23.tv/ovDovTD
> **发布**：2026-06（系列终篇）· 3 分 29 秒

### 一句话核心

> **先想 UX（用户怎么交互），再做 UI（按钮长什么样）。**
> **最聪明的解法往往是：把"丑按钮"问题从 UI 层抹掉，改成 UX 层换个交互范式。**

### 基础概念区分

| 概念 | 英文 | 定义 |
|---|---|---|
| **UI** | User Interface | 某个按钮、某个布局**看起来怎么样** |
| **UX** | User Experience | **用户的体验、交互** |

**最小例子**：

| 控件 | UI 一样 | UX 不一样 |
|---|---|---|
| Date Input | 都是日期输入框 | 一个是**输入** |
| Date Picker | 都是日期选择器 | 一个是**选择** |

### 真实案例 · 印书 AI 生图功能

#### 问题

印书有一个 AI 生图功能，有很多模板可选。

**用户痛点**：用户选择生成之前，并不知道生成的结果是什么样——只能看到生成后的样式。

#### 第一次尝试（UI 层 · 失败）

加一个按钮，让用户**翻转查看生成前的样子**。

> "翻转了之后，他就可以知道说生成前是什么样子。**然后我就遇到了一个问题：好丑啊。** 怎么办呢？"

#### 第二次解法（UX 层 · 成功）

> "事实上我**完全舍弃了按钮这个交互**——也就是说我不用再去思考说这个按钮应该是圆的还是方的、放在中间还是上面、还是点击图片。"
>
> "因为点击图片现在已经有了一个交互的逻辑——就是**确认风格**。所以我不再去思考说这个按钮怎么的问题。"
>
> "我做的是**UX 层面上的变化**——我把它从之前的**点击切换逻辑**，变成了一个**自动播放逻辑**。所有的风格都是如此。"

#### 效果

✅ 不再有"丑按钮"问题
✅ 用户体验更自然（被动看变体比主动点击翻转流畅）
✅ 代码也更简单（少一个按钮的状态管理）

### 终极心法

> "**你在设计任何一个功能之前，先去想一下你希望用户的交互是什么样子的**——是滑动、还是点击、还是输入、还是拖拽、还是长按、还是点按——**这些想好了之后**，才踩到 UI 的问题：他怎么样好看、放到哪里、跟其他的整个空间是什么样子的。"

### 关键引用

> "**我完全舍弃了按钮这个交互。**"

> "我做的是 UX 层面上的变化。"

> "**先想用户的交互是什么（滑动 / 点击 / 输入 / 拖拽 / 长按 / 点按），再想 UI 怎么好看。**"

## 五、行动清单

### 第一步 · 审美积累（第一集）
- [ ] 立刻下载 6 个 App 把玩：记绩、印书（Margins）、感叹号天气、未知书、Apollo、Pinterest
- [ ] 在手机建一个文件夹叫"审美素材库"，看到喜欢的交互/动效**就截图录屏**
- [ ] 每周固定 30 分钟**刷 Pinterest 收藏夹**

### 第二步 · Style.md（第二集）
- [ ] 挑一个最想做的功能，扔 2 张参考图给 AI
- [ ] 让 AI 帮你聊 PRD（产品定位 + 流程）
- [ ] 让 AI 生成 5 个 mockup 变体，**做选择题**
- [ ] 让 AI 输出 **style.md**（字体 / 间距 / 颜色 / 文案语气）
- [ ] **把 style.md 存到项目根目录**，每次开新功能**@ 它**

### 第四步 · UX 先于 UI（第四集）
- [ ] 设计任何新功能时，**先写一段"用户怎么操作"的文字描述**
- [ ] 想清楚 5 种交互范式：滑动 / 点击 / 输入 / 拖拽 / 长按
- [ ] **遇到"按钮怎么放都丑"时，退回 UX 层换个交互范式，别死磕 UI**

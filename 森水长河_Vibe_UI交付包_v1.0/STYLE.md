# 森水长河小程序 Vibe UI / UX 视觉交互规范（STYLE.md）

## 1. 产品气质

森水长河不是传统景区工具，也不是普通商城。界面应同时具备：

- **自然探索感**：森林、河流、营地、溪降。
- **轻奢度假感**：克制、留白、光影、低饱和配色。
- **现场行动感**：用户必须快速知道“现在能做什么、下一步去哪里”。
- **沉浸游戏感**：长河令是另一种“江湖资产”，允许独立深色主题。

禁止：模板化渐变、满屏描边、同质化白卡、每一行都放按钮、过度卡通化、廉价电商红。

## 2. 核心设计原则

1. **先 UX 后 UI**：先定义点击、滑动、长按、拖动、上滑半屏、自动切换，再画控件。
2. **整块可触摸**：列表项和任务卡本身就是操作区；除交易确认外，减少“去完成/查看详情”按钮。
3. **双主题而非全局黑白切换**：
   - 向导、地图、预约、商城、我的：自然浅色主题。
   - 长河令、悬赏、侠客资产、拍卖：沉浸深色主题。
4. **动态材质**：底部导航随页面主题切换浅/深毛玻璃；卡片层次随滚动轻微变化。
5. **信息优先**：天气、水位、营业、活动时间、名额、预约号必须一眼可见。

| `text-secondary` | `#7D867F` | 次级文字 |
| `forest` | `#244B36` | 品牌主色、主按钮 |
| `forest-deep` | `#173628` | 深绿背景/强调 |
| `moss` | `#3A6749` | 次级绿色 |
| `gold` | `#D5A43A` | 长河令、奖励、会员 |
| `coral` | `#F07055` | 交易型 CTA、强提醒 |

### 色彩纪律

- 一个页面最多一个强 CTA 色；主交易用 coral，品牌行动用 forest。
- 金色仅用于长河令、奖励、会员权益，不用于普通装饰。
- 深色页禁止纯白大面积卡片；浅色页禁止纯黑大面积按钮。

## 4. 字体与数字

- 中文：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 数字：优先系统几何数字；使用 `font-variant-numeric: tabular-nums`。
- 大资产数字：64–88rpx、字重 800–900、紧凑字距。
- 页面标题：48–56rpx / 700。
- 区块标题：32–36rpx / 650–700。
- 正文：28rpx；辅助说明：22–24rpx。
- 不在小程序里远程加载未经授权的字体文件。

## 5. 圆角、间距、阴影

- 页面左右安全间距：32rpx。
- 基础网格：8rpx。
- 小卡片圆角：24rpx；主卡片：32–40rpx；沉浸资产卡：56–64rpx。
- 卡片内边距：24/32/40rpx三级。
- 浅色卡片阴影：`0 12rpx 40rpx rgba(30,55,40,.06)`，只给重点卡片。
- 深色卡片不用重阴影，靠明度差和弥散光建立层次。

## 6. 页面主题

### 6.1 向导 / 首页

- 使用大场景图 + 实时状态卡；首屏回答：开不开、水位如何、几点活动、我预约了什么。
- 快捷入口不超过四个；高频功能“大卡 + 两个小卡”。
- 今日活动采用时间轴，不堆九宫格。

### 6.2 园区地图

- 地图占据主要视野；POI 采用短标签，避免大量永久悬浮。
- 点击 POI 不跳页，先上滑半屏卡片；二次操作再进入详情/导航。
- “我在这里”必须有明显呼吸定位点。

### 6.3 长河令

- 默认深色 `#121212`。
- 资产卡不用边框堆砌，使用内部弥散光 + 超大余额数字。
- 任务列表整行可点击；按下缩放、轻振动；禁止每条都加“去完成”。
- 奖励、余额、拍卖使用金色；危险和过期使用珊瑚红。

### 6.4 溪降预约

- 日期横滑、时段单选、项目卡片单选、名额实时显示。
- 上车号是一个“现场资产”，需要大号显示并支持前台更新。
- 安全须知默认摘要，点击/上滑查看完整内容，不占满首屏。

### 6.5 商品与服务

- 酒吧与租赁按场景分组，不做传统多级类目商城。
- 商品卡图片优先，价格与加号清晰；营位配送固定显示目标营位。
- 购物车为底部悬浮结算条，加入商品时做轻微弹性反馈。

### 6.6 我的 / 会员

- 首屏展示身份、会员卡、订单、钱包；设置类入口放在后半屏。
- 9.9会员卡采用深绿 + 极淡金色纹理，避免大红促销感。

## 7. 动效规范

| 场景 | 动效 | 时长 | 曲线 |
|---|---|---:|---|
| 卡片按下 | scale `1 → .96` | 100–140ms | ease-out |
| 主 CTA 按下 | scale `1 → .94` + 亮度降低 | 100–120ms | ease-out |
| 页面进入 | opacity + translateY(16rpx) + scale(.985) | 280–380ms | `cubic-bezier(.16,1,.3,1)` |
| 半屏卡片 | 自底部弹入 | 320–420ms | spring-like |
| Tab 切换 | 图标缩放 + 标签淡入；导航材质交叉淡化 | 240–320ms | ease |
| 余额变化 | 数字滚动/递增 | 400–700ms | ease-out |
| 状态刷新 | 标签颜色渐变，不闪烁 | 180–240ms | ease |

动效纪律：

- 动效必须解释状态变化，不做无意义漂浮。
- 同一时间最多一个主动画。
- 列表滚动中不触发复杂模糊和大量阴影重绘。

## 8. 触觉反馈

- 普通卡片：轻振动，仅在明确操作完成时触发，不在每次 touchstart 都触发。
- 领取长河令、预约成功、支付成功：中等振动。
- 风险确认、取消预约：较强振动。
- 滑动浏览、普通滚动：不振动。

## 9. 无按钮化交互

优先级：

1. 整卡点击。
2. 横向滑动选择。
3. 上滑半屏详情。
4. 长按预览/领取。
5. 自动轮播展示状态变化。
6. 最后才使用独立按钮。

必须保留按钮的场景：支付、预约确认、取消、退款、授权等不可逆或关键交易。

## 10. 图标规范

- 图标资源统一来自 `assets/icons/`。
- 浅色页面使用 `forest`；深色页面使用 `ivory`。
- 常规图标显示 36–48rpx；快捷入口 48–60rpx；底部导航 48–56rpx。
- 图标与文案间距 12–16rpx。
- 禁止同一页面混用 Emoji、FontAwesome、系统图标和不同线宽 SVG。

## 11. 验收红线

- 不允许随意增加新色值、新圆角、新阴影。
- 不允许每个模块都变成白色圆角卡片。
- 不允许为了“高级”而降低文字对比度。
- 不允许动效导致点击延迟、列表掉帧、页面跳动。
- 不允许把参考 App 的视觉原样复制；只继承交互哲学和层次方法。
